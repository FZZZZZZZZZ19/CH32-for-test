## 1. 一分钟版本

* **一份固件**：`User/main.c`（26 行）只做 `clock_init → debug_init → app_main_init → while(1) app_main_loop()`。
* **三层结构**：`app_main`（调度器/模式）→ `app_port`（板级绑定，唯一引脚事实源）+ 各功能模块 → 纯逻辑模块（可 PC 单测）。
* **不重烧录**：上电进自检，随后停在三级菜单；11 个演示功能、8 个参数、参数存取全部由板上按键切换；
  按键走**手势通路**（短按翻项、长按确定/提交并自动存 Flash、双击返回），板上任意 1~2 个键都能操作；摇杆左长按直接回主菜单。
* **自证手段**：屏幕状态行（`#任务号 L灯掩码 E外部中断数 C按键原始编码`）+ 演示态第 1 行按键回显（`KEY UP C3`）+ 每次按键蜂鸣器短鸣 + UART3 115200 日志 + `SELF TEST` 自检 8 项。
* **代码量**：`User/app_*` 共 31 个文件 3438 行（纯逻辑 6 个模块可在 PC 上单测，2192 项断言全通过）。

## 5. 现场操作剧本（不重新烧录）

1. **上电**：屏幕显示自检过程，串口打印版本/引脚表/参数槽位；
   自检 8 项结果以 `[SELFTEST] xxx OK` 逐行输出，失败位掩码会打印在末尾。
2. **主菜单**：板上任意键**短按**翻项、**长按**确定进入、**双击**返回（手势通路，1~2 个键就能操作）；
   若五向开关可用，也可 `DOWN` 下移 / `ENTER`(中键) 进入 / `BACK`(左) 返回。
   主菜单三项：`DEMO` / `PARAMETERS` / `SYSTEM`。
3. **看细则 3/4**：进 `DEMO → LED`，短按切「流水 / 全亮 / 全灭」；
   进 `DEMO → KEYS`，把板上能按的都按一遍（两个白色轻触键、五向开关四个方向与中间），
   观察状态行 `C` 编码与键名（注意"上"不可分辨，见 §6）。
4. **看细则 5/6**：进 `DEMO → PWM OUT`，H1 的 3 个引脚接示波器/蜂鸣器，观察自动扫频；
   进 `DEMO → BUZZER`，按键重复鸣叫；
   进 `DEMO → TIMER LED`，看 LED6 按参数周期亮灭、计数在涨（中断里翻转）。
5. **看细则 7/9**：进 `DEMO → SCREEN`（进度条动画）；进 `DEMO → UI PANEL`（4 个 tile 交互）。
   演示态下：**短按**给该演示用，**长按**切下一个演示，**双击**回到菜单。
6. **看细则 8/10**：
   * 进 `PARAMETERS`，选 `BLINK MS` **长按**进三级编辑页；**短按**加、另一个键减（或 `R`/`KEY2`）；
     **长按**提交并**立即写入 Flash**（屏幕提示 `PARAM SAVED`），**双击**取消；五向开关可用时 `ENTER` 提交、`BACK` 取消；

7. **看细则 9 的外部中断**：进 `DEMO → EXTI KEY`，按键交替「重装 EXTI / 关闭 EXTI」，

## 6. 高频提问与标准答案

**Q1：为什么可控 LED 只有 4 个，不是 8 个？**
A：LED1–LED4 经 RN4 分别接 5V / 3.3V / 3.3V_MAIN / 3.3V_CAM，是电源指示灯，MCU 不可控；
真正的 MCU 控制通道只有 RN3 的 4 路：PD1/PA15/PA12/PA11 → LED5–LED8，且**高电平点亮**。

**Q2：为什么五向开关的"上"不能用？**
A：74HC148 的 `GS`/`EO` 没接到 MCU，MCU 只能读 3 位编码。"上"接在优先编码器的最高优先输入 I0，
其编码是 `111`，与"无键（输入全高）"完全相同，硬件上不可区分；而且按住"上"会屏蔽其它键。
所以固件把 `111` 当无键，用独立按键 `KEY1`（`011`）承担"上"的导航职责。

**Q3：立创 EDA 符号上 pin13 标的是 I3，为什么你说它是 I0？**
A：以物理引脚和数据手册为准。TI SN74HC148：pin13 = I0、pin12 = I1、pin11 = I2、pin10 = I3
（符号内部标注与数据手册相反）。板上走线连的是物理引脚，固件也按物理引脚建模，并在 `docs/PINMAP.md` 记录了这个坑。

**Q4：为什么用 Flash 扇区 63？掉电会不会丢？**
A：Link.ld 只用前 256KB，最后 4KB（扇区 63）不会被动到。每个槽 44 字节，含 magic/版本/长度/序号/CRC32；
A/B 双槽轮换：每次保存都写"非当前槽"并把序号 +1，上电时取序号大且 CRC 正确的一槽，单槽写坏仍能用另一槽；
写入前先擦 1KB 一页，失败会中止并保留旧数据；参数反序列化后还会再夹取一次范围。

**Q5：为什么按键扫描放在主循环，不放在中断里？**
A：1ms 节拍中断只做两件事（`app_tick_ms++`、中断内翻 LED），保证中断极短；
按键消抖/长按/连发/菜单/UI 都在主循环（10ms 扫描 / 50ms 刷新），没有 ISR 与主循环共享队列的竞争问题。
外部中断（PD8）只累加计数与记录时间戳，也不做业务逻辑。

**Q6：三路 PWM 的频率可以不同吗？**
A：同一定时器内的通道频率必须相同（本次三路分属 TIM3 与 TIM4，仍统一设为同一频率），占空比可独立。

**Q7：屏幕为什么是英文？**
A：逐飞 `tft180` 驱动只内置 ASCII 点阵（`zf_common_font.h` 只有 6×8 / 8×16 与少量中文字模），
要中文需自备字模数组，因此界面统一用 8×16 ASCII，信息密度和可读性都够。

**Q8：怎么证明这些功能真的在工作，而不是"看着像"？**
A：三条自证链：
① 屏幕状态行 `#任务号 L灯掩码 E外部中断数 C按键原始编码`（最长 14 列，不会触屏驱动断言）实时刷新；
   演示态下第 1 行还有 `KEY UP C3` 回显（按键名 + 74HC148 原始编码），并且每按一次键蜂鸣器响 40ms，
   所以"按键到底有没有被 MCU 读到"是看得见也听得见的；
② UART3 115200 日志打印上电信息、参数存取、自检逐项结果；
③ `SELF TEST` 自检把 8 个子系统跑一遍并汇总失败掩码（LED 回读、按键编码、PWM 回读、蜂鸣器开关、屏幕色带、Flash 槽位、EXTI、参数序列化回环）。

**Q9：为什么 144MHz？**
A：`clock_init(SYSTEM_CLOCK_144M)`，8MHz 晶振倍频；PWM/SPI 分频都在 144MHz 下计算。

**Q10：用了逐飞库的哪些部分？**
A：`zf_driver_gpio`（LED/按键/背光）、`zf_driver_pwm`（3 路 PWM + 蜂鸣器）、`zf_driver_pit`（TIM6 1ms 节拍）、
`zf_driver_exti`（PD8 双边沿）、`zf_driver_flash`（参数存储）、`zf_device_tft180`（ST7735 屏）、`zf_common_clock/interrupt`、
`Debug/debug.c`（printf 重定向到 UART3）。

**Q11：如果现场要改成"按键控制 LED 亮灭"（盲盒常见变体），改哪里？**
A：只改 `app_main.c::app_main_handle_event` 里的映射（例如把 `ENTER` 事件映射到 `app_led_toggle`），
或直接加一个演示分支；引脚层与按键层都不用动 —— 这正是分层的目的。

**Q12：屏幕上显示 `Assert error file :zf_device\zf_device_tft180.c line:409` 是怎么回事？**
A：这是"上屏文本超过屏幕宽度"触发的驱动断言，不是硬件故障。`tft180_show_string()` 不换行也不裁剪，
第 j 个字符画在 `x + 8*j`；屏幕 128 像素 ÷ 8 像素 = 16 列，第 17 个字符就落在 `x = 128`，
撞上 `tft180_show_char()` 的 `zf_assert(x < tft180_x_max)`（`zf_device_tft180.c:409`）。
开机进演示会立刻画状态栏，旧版状态栏最坏 24 字符（`#1 L15 E999 T999 F1 9999`）⇒ 一上电就断言；
又因为 `tft180_init()` 把 TFT 注册成了 debug 输出设备，而 `debug_assert_handler()` 是 `while(1)` 循环打印，
所以屏幕永远停在那句话（`zf_common_debug.c:365`）。
修复：① 状态栏与编辑详情行压到 ≤16 列；② `app_screen_text()` 增加行列越界 + `app_text_clip()` 16 列裁剪双保险，
以后即使有人写超宽字符串也只是被截断，不会再断言；③ `host_test/test_ui.c` 把"每一行 ≤16 列"做成回归测试
（临时把旧状态栏放回去会立刻报 47 处失败，证明这条测试有效）。

**Q13：板上到底有几个按键？为什么一开始"按了没反应"？**
A：原理图上键盘是 **7 个开关接 8→3 优先编码器**：两个轻触键 `SW14`(`KEY1`)、`SW15`(`KEY2`)
   加一个五向开关 `U / L / D / M / R`，全部接到 `U15`（`SN74HC148DR`）的输入，编码器再把 3 位编码送到
   `PB14(A2) / PB12(A1) / PD8(A0)`——所以固件看到的是"编码"，不是 7 个独立引脚。
   实物板上能看到的对应件：**右下角两个白色轻触键 + 紧挨着的黑色方形金属壳五向开关（中间可按、四个方向可推）**，
   旁边那个黑色圆片是蜂鸣器，左下角的金属拨杆是电源开关。
   可分辨的编码只有 **6 个**：`000=KEY2`、`001=中键 M`、`010=右 R`、`011=KEY1`、`101=左 L`、`110=下 D`；
   五向开关"上"（I0）的编码与"无键"同为 `111`（`GS/EO` 没接到 MCU，见 `docs/PINMAP.md` 第 3.3 节），
   所以固件让 `KEY1` 兼作"上"。
   现场实测（用户板）：按白色轻触键能把光标移动、状态行 `E`（PD8 外部中断计数）会累加，
   **说明编码器与按键链路本身是通的**；当时"另一个键按了没反应"的真正原因是
   旧版把 `KEY2`(000) 只映射成"编辑态减"，在列表态什么都不做 —— 属于固件 UX 问题，不是硬件问题。
   现在的版本加了一层**手势通路**，因此**任意 1~2 个键都能走完三级菜单**：
   ① **短按** = 上/下翻项（编辑态 = 加/减）；② **长按 ≥1 s** = 确定（进入下一级 / 提交编辑并立即写 Flash）；
   ③ **双击（两次短按 < 400 ms）** = 返回上一级 / 取消编辑。同时保留原 6 个编码的直接语义。
   想看按键原始状态：状态行 `#任务 L灯 E中断数 C编码`（无键 `C7`，KEY1 `C3`、中键 `C1`、下 `C6`、左 `C5`、右 `C2`、KEY2 `C0`），
   演示态第 1 行还有 `KEY <名字> C<编码>` 回显，按下即有蜂鸣器短鸣。
   若 `C` 一直是 7，才需要查硬件（`U15` 是否焊接、`RN1/RN2` 上拉、`EI` 接地）。
   上电行为：`PARAMETERS → BOOT DEMO = 0`（默认）停在菜单，改成 1..11 上电直接进第 `值-1` 号演示，同一份固件不用重烧。

## 8. 已知限制（主动说明，避免被追问）

1. "上"方向键不可用（硬件未接 GS/EO），已用 `KEY1` 代偿。

4. 屏幕 128×160、8×16 字体 ⇒ 16 列 × 10 行，列表窗口一次显示 6 行（滚动显示）。
5. 主机端单测只覆盖纯逻辑模块，硬件路径依赖板上 `SELF TEST`。
6. `tools/build.ps1` 内写死本机工具链路径（MounRiver IDE 编译不受影响）。
