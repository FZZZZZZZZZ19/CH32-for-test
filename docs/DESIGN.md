## 2. 分层结构（为什么这样分）

```
main.c            仅做时钟/串口初始化，然后交给 app_main()
 └ app_main.c     协作式调度器（1ms/10ms/50ms/100ms 时基）+ 模式管理（免重烧录切换）
    ├ app_port.c        板级绑定：LED 引脚表、按键编码表、JTAG→SWD 释放
    ├ app_time.c        TIM6 1ms 节拍（中断只做计数）
    ├ app_key.c         按键采集/消抖/事件队列 + EXTI 计数
    ├ app_led.c         LED 模式引擎 + 中断内翻转接口
    ├ app_pwm.c         三路 PWM 频率/占空比（含同定时器约束处理）
    ├ app_buzzer.c      无源蜂鸣器音调（非阻塞）
    ├ app_screen.c      TFT180 文本/图形封装（行缓冲 API）
    ├ app_ui.c          菜单/演示两种界面的按键解释与渲染
    ├ app_menu.c        ★纯逻辑：三级菜单状态机（可在 PC 上单测）
    ├ app_params.c      ★纯逻辑：参数序列化 + CRC32 + 双槽选择；flash 存取（仅目标端）
    ├ app_crc32.c       ★纯逻辑：CRC-32/ISO-HDLC
    ├ app_demo.c        11 个功能演示（与细则一一对应）
    └ app_selftest.c    上电自检与报告
```

★ 标记的模块**不包含任何硬件头文件**，可以脱离目标板用 gcc 编译，被 `host_test/` 里的单元测试直接验证（细则第 3/4/8/10 项的逻辑部分因此有可复现证据，而不是"上板看现象"）。

## 3. 硬件绑定的关键判读（容易踩的坑）

1. **右侧 LED 只有 4 个受 MCU 控制**：LED1..LED4 由 RN4 直接接 5V/3.3V/3.3V_MAIN/3.3V_CAM，是电源指示灯；LED5..LED8 才由 RN3 拉到 PD1/PA15/PA12/PA11，**高电平点亮**（阳极接 MCU 侧，阴极共地）。`LIGHT4_C10` 在本板未接 LED。
2. **PA15 是 JTDI**：不复用 JTAG 引脚时它不能当普通 GPIO。逐飞库只提供 `GPIO_Remap_SWJ_Disable`（会把 SWD 一起关掉，之后无法下载调试），所以 `app_port.c` 直接写 `AFIO->PCFR1` 的 `SWJ_CFG=001`（JTAG-DP 关、SW-DP 保留）。**烧录/SWD 调试不受影响，PA15 变成普通 IO。**
3. **74HC148 的 U 方向无法识别**：GS/EO 没接到 MCU，`pin13=I0=U` 的编码 111 与"无按键"完全相同（见 `docs/PINMAP.md` 真值表）。固件把 111 判为"无按键"，用 `KEY1(011)` 代替"上"、`KEY2(000)` 作为功能键；同时把 `D/L/R/M` 四个方向保留给菜单导航。原理图符号内部标注（13/12/11/10 标成 3/2/1/0）与 TI datasheet 相反，固件以**物理引脚**为准。
4. **屏幕和蜂鸣器都是"低阻驱动 + 高有效"**：屏幕 BLK 高电平开背光；蜂鸣器经 AO3400A N-MOS 驱动（PA8 高 → 导通），是**无源**蜂鸣器，必须给 2.7kHz 左右方波才响。
5. **TIM4 的两路 PWM（PD14/PD15）共用一个定时器**：频率必须一致，占空比可独立；`app_pwm.c` 把频率设置做成"改频率后统一重设三路占空比"，避免只改 ARR 导致另一路占空比漂移。
6. **PA13/PA14 是 SWDIO/SWCLK**，固件全程不碰；`PB13/PB15` 是屏幕 SPI，`PB12/PB14/PD8` 是按键编码输入。

## 4. 免重新烧录（细则第 11 项）怎么做到

- 上电后进入 `BOOT DEMO` 参数指定的功能页；所有功能页与三级菜单都在同一个 `while(1)` 调度器里，切换只是改一个索引。
- 全局快捷键：`KEY2` 长按 1s → 回主菜单（任何界面任何时刻有效）；`KEY1` 长按 1s → 下一个功能；`L` → 返回/上一级。
- 参数改动存 flash（双槽 + CRC），重新上电后仍然生效，因此"换功能/换参数"都不需要重新编译或重新烧录。

## 5. 自证方法（验收怎么跑）

1. `host_test/`：`make test` 用 PC 的 gcc 编译 ★模块并跑断言（CRC32 标准向量、参数双槽选择、参数夹取、三级菜单导航/回退/编辑/越界）。
2. 目标端编译：用 xPack riscv-none-embed-gcc 8.2.0 以工程同参数编译（见 `docs/BUILD.md`），要求 **0 error 0 warning**；给出 `text/data/bss` 数字。
3. 上板：串口 115200（UART3 PB10/PB11）打印自检报告与按键事件；屏幕显示同一份信息，两边可对照。

## 6. 已知限制（答辩时主动说明）

- 8x16 ASCII 字库在 128x160 竖屏上只能显示英文/数字；中文界面需要自备 16x16 点阵（`tft180_show_chinese` 已预留接口，本工程未内置中文字模）。
- 自检里"屏幕/PWM/蜂鸣器"是**初始化级**检查（驱动返回 + 寄存器回读），不是像素/波形回读；像素级验证仍需人眼或示波器。
- `flash_erase_sector()` 逐页 1KB 擦除，每次保存都擦一遍，频繁保存会消耗擦写寿命（本工程只在按键保存时写，且 A/B 轮换）。
- U 方向按键的硬件缺陷见第 3 条第 3 点，属于原理图问题，固件已给出替代操作方式。
